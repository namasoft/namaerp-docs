# تعريفات أدوات الذكاء الاصطناعي (AI Tool Definitions)

عندما يتحدث مساعد ذكاء اصطناعي مع نظام نما ERP — سواء كان المساعد المدمج داخل النظام أو عميلًا خارجيًا متصلًا عبر [خادم MCP](./ai-mcp-server.md) — فهو لا يستطيع فعل أي شيء من تلقاء نفسه. كل قدرة يملكها المساعد هي **أداة (Tool)** عرّفها مدير النظام مسبقًا: استعلام يجيب عن سؤال معين، تقرير يشغَّل بمدخلات، مسار كيان ينفَّذ على مستند، أو أداة نظامية جاهزة من أدوات نما.

شاشة **AI Tool Definition** في وحدة الذكاء الاصطناعي هي المكان الذي تُعرَّف فيه هذه الأدوات. كل سجل في الشاشة يصبح أداة (أو مجموعة أدوات) يستطيع النموذج اللغوي استدعاءها، مع وصف يخبره متى وكيف يستخدمها.

::: info الترخيص المطلوب
تتطلب هذه الشاشة تركيب وحدة الذكاء الاصطناعي (AI Module) وترخيصها ضمن رخصة النظام.
:::

![شاشة AI Tool Definition — الصفحة الرئيسية وجدول الصلاحيات](./images/ai-tool-definition-main-ar.png)

## البيانات الأساسية

في رأس الشاشة تحدد هوية الأداة وسلوكها العام:

| الحقل | الدور |
|---|---|
| **Tool Type** | نوع الأداة: `Query Based` أو `Report Based` أو `Entity Flow Based` أو `System Tool` — وهو ما يحدد أي صفحة من صفحات الشاشة ستُستخدم |
| **Alt Code** | الاسم الذي تُعلَن به الأداة للنموذج اللغوي في الأنواع الثلاثة الأولى (استعلام/تقرير/مسار كيان) |
| **Tool Name (Must Be Unique)** | في أدوات النظام (System Tool) يُستخدم كبادئة لأسماء الأدوات المتولدة — انظر «تسمية الأدوات» أدناه |
| **Description** | وصف الأداة. هذا الحقل **هو ما يقرؤه النموذج اللغوي ليقرر متى يستدعي الأداة وكيف** — فكلما كان الوصف أدق وأوضح، كان استخدام النموذج للأداة أصوب |
| **In Active** | تعطيل الأداة دون حذفها — الأداة المعطلة لا تُعرض على النموذج إطلاقًا |

::: tip متى تظهر الأداة للمساعد؟
لا تُعرض الأداة على النموذج اللغوي إلا إذا كانت **معتمدة (Committed)** وغير معطلة. وأي تعديل أو حذف لاحق ينعكس تلقائيًا — يعاد بناء قائمة الأدوات عند أول اتصال تالٍ دون الحاجة لإعادة تشغيل.
:::

### تسمية الأدوات

- أدوات **الاستعلام والتقرير ومسار الكيان**: تُعلن الأداة باسم **Alt Code** كما هو.
- **أدوات النظام (System Tool)**: كل سطر في جدول الأدوات قد يولّد أداة أو أكثر، ويتركب اسم كل أداة من بادئة + اسم الأداة الداخلي. البادئة هي أول قيمة غير فارغة من: **Tool Name** ثم **Alt Code** ثم **الكود**، يليها شرطة سفلية. فمثلًا سجل كوده `import` يحتوي صنف `AITReadRecordTools` يولّد أداتين اسمهما `import_FindRecords` و `import_GetRecord`.
- **كل أداة**، من أي نوع، تأخذ أيضًا خمسة مدخلات اختيارية لا تعرّفها أنت: `loginLegalEntity` و`loginSector` و`loginBranch` و`loginDepartment` و`loginAnalysisSet`. وهي تنفّذ النداء كأن المستخدم سجّل دخوله على تلك المحددات — انظر «اختيار سياق الدخول» في صفحة [خادم MCP](./ai-mcp-server.md).

## الصلاحيات (التحكم في الوصول)

جدول **الصلاحيات (التحكم في الوصول)** يحدد من يستطيع تنفيذ الأداة. كل سطر يحمل:

- **Applicable For**: مستخدم، أو ملف أمان (Security Profile)، أو مجموعة مستخدمين.
- **Allow / Prevent**: سماح أو منع.

عند تنفيذ الأداة يبحث النظام عن أول سطر ينطبق على المستخدم الحالي بهذا الترتيب: سطر **المستخدم** نفسه أولًا، ثم سطر **ملف الأمان** الخاص به، ثم سطر **المجموعة**. أول سطر مطابق يحسم القرار. وإذا كان الجدول فارغًا (أو لا يوجد سطر مطابق) فالأداة متاحة للجميع.

::: warning الصلاحيات تُفحص مرتين
لا يُعرض على العميل إلا الأدوات التي يحق لمستخدمه تشغيلها: الأداة التي يمنعها هذا الجدول عن المستخدم لا تظهر في قائمة أدواته أصلًا، في عميل MCP أو في المساعد الداخلي. فعبارة «المستخدم س لا يرى الأداة ص» سببها في الغالب هذا الجدول، لا عطل. ثم يُفحص **التنفيذ** مرة أخرى: نداء أداة ممنوعة يُرفض برسالة واضحة. كما تظل جميع صلاحيات السجلات والمحددات (الشركة، الفرع، ...) سارية على ما تقرؤه الأداة أو تكتبه، لأن كل شيء يمر عبر بوابة الخدمات القياسية للنظام.
:::

## النوع الأول: أداة مبنية على استعلام (Query Based)

أبسط أنواع الأدوات وأكثرها استخدامًا: استعلام SQL يكتبه مدير النظام، ويستطيع النموذج اللغوي تشغيله بمدخلات يحددها هو.

في صفحة **Query Based**:

1. اكتب الاستعلام في حقل **Query**، مع الإشارة إلى كل مدخل بصيغة العنصر النائب `{paramName}` (مثل `{fromDate}` و `{toDate}`).
2. عرّف كل مدخل في جدول **Query Parameters**.
3. اكتب في **Description** متى ينبغي استخدام هذه الأداة وماذا تُرجع.

عند التنفيذ يُشغَّل الاستعلام بقيم المدخلات التي أرسلها النموذج، وتُعاد النتيجة له بصيغة JSON (أسماء الأعمدة وقيم الصفوف).

::: tip المدخلات الاختيارية والشرطية
تمرّ مدخلات الاستعلام عبر المحرك نفسه المستخدَم في SQL الخاص بخرائط الحقول (Field Maps)، لذا تتوفر صيغة [مدخلات SQL المتقدمة](../../../entity-flows/core/ai-generated-field-maps-documentation.md#Advanced-SQL-Parameter-Syntax) كاملةً — وليس مجرد العنصر النائب البسيط `{fromDate}`. وهذا مهم لأن أداة الذكاء الاصطناعي تعرض عادةً عدة فلاتر *اختيارية*، وتتيح هذه الأدوات المساعدة لاستعلام واحد أن يتعامل معها سواء أرسل النموذج قيمةً أم لا:

- `{x>=,valueDate,fromDate}` — مقارنة تتحول إلى `1 = 1` (بلا أثر) عندما لا يرسل النموذج المدخل `fromDate`، بدلًا من إحاطة كل فلتر بالشكل `({fromDate} IS NULL OR ...)`.
- `{xBetween,column,fromDate,toDate}` — نطاق قد يغيب أحد طرفيه.
- `{xIN,column,codes}` — جملة IN تتحمل القائمة الفارغة دون خطأ.
- `{!paramName}` — استبدال نصي مباشر (لأسماء الجداول أو الأعمدة الديناميكية؛ ولا يُستخدم أبدًا مع مدخلات غير موثوقة).
:::

![صفحة Query Based وجدول مدخلات الاستعلام](./images/ai-tool-definition-query-ar.png)

### جدول المدخلات

كل سطر في جدول المدخلات يعرّف مدخلًا واحدًا:

| العمود | الدور |
|---|---|
| **Param Id** | معرف المدخل — يجب أن يطابق الاسم المستخدم في الاستعلام، ولا يجوز تكراره |
| **Parameter Description** | وصف المدخل الذي يقرؤه النموذج ليعرف ماذا يرسل |
| **Required** | هل المدخل إلزامي |
| **Field Type** | نوع القيمة: `Text` أو `Number` أو `Date` أو `Reference` |
| **Allowed Values** / **Allowed Values Ar** / **Allowed Values En** | قائمة القيم المسموحة (إن وجدت) مع ترجماتها — تُعرض للنموذج ضمن وصف المدخل ليلتزم بها |
| **Supported Reference Type** | عند اختيار النوع `Reference`: نوع الكيان الذي يشير إليه المدخل (مثل `Customer`) |

ملاحظات على الأنواع:

- **Date**: يرسل النموذج التاريخ بصيغة `yyyy-MM-dd HH:mm` (تُذكر له هذه الصيغة تلقائيًا في وصف المدخل).
- **Reference**: يستطيع النموذج إرسال كود السجل أو معرفه فيُبحث عنه مباشرة. وإذا أرسل نصًا حرًّا (مثل اسم عميل تقريبي) والكيان مفهرس في خدمة التضمين الدلالي (Records Embedding)، يبحث النظام بحثًا دلاليًا ويعيد أقرب السجلات — وإن تعددت النتائج طُلب من النموذج اختيار سجل محدد منها.

## النوع الثاني: أداة مبنية على تقرير (Report Based)

تحوّل أي تعريف تقرير (Report Definition) موجود في النظام إلى أداة يستطيع النموذج تشغيلها وقراءة مخرجاتها.

في صفحة **Report Based**:

1. اختر التقرير في حقل **Report Definition**.
2. عرّف مدخلات التقرير في جدول **Report Parameters** — لكل مدخل من مدخلات التقرير سطر، **Param Id** فيه يطابق معرف مدخل التقرير.
3. حدد لكل مدخل طريقة تعبئته في عمود **AI Parameter Completion**:
   - **Fill By AI**: يحدد النموذج اللغوي القيمة بنفسه بناءً على طلب المستخدم (مع وصف المدخل والقيم المسموحة كما في أدوات الاستعلام).
   - **Fill Manually**: تُثبَّت القيمة في التعريف نفسه — قيمة نصية أو مرجع أو تاريخ/وقت أو قيمة ديناميكية، بنفس أسلوب مدخلات التقارير في جدولة المهام — ولا تُعرض على النموذج أصلًا.

عند التنفيذ يُشغَّل التقرير بالمدخلات المجمعة، ويُعاد ناتجه **نصًّا** إلى النموذج ليقرأه ويبني عليه إجابته.

![صفحة Report Based وجدول مدخلات التقرير](./images/ai-tool-definition-report-ar.png)

::: warning اختيار التقرير يملأ الجدول مرة واحدة — ويجمّد مسميات القائمة
اختيار تقرير في **Report Definition** يعيد بناء جدول **Report Parameters** من تصميم التقرير نفسه: سطر لكل مدخل، بنوعه، وهل هو إلزامي، وللمدخل الذي يعرض قائمة اختيار تُنقل قيمه إلى عمود **القيم المسموح بها** ومسمياتها العربية والإنجليزية إلى عمودي **Arabic Allowed Values** و **English Allowed Values**.

وهذه المسميات تُنسخ كما هي في تلك اللحظة ولا تُقرأ مرة أخرى أبدًا. وهي ما يُعرض على النموذج باعتباره القيم التي يقبلها المدخل، فإن غيّر أحدهم مسمى قيمة لاحقًا من شاشة تعديل الترجمات (Translation OverRider) ظهر المسمى الجديد في شاشة تشغيل التقرير بينما تظل الأداة تعرض على النموذج المسمى القديم، دون أي تنبيه. وينطبق الأمر نفسه على تقرير تغيّرت مدخلاته بعد بناء الأداة: الجدول لا يتبعه.

وعلاج الحالتين واحد: أعد اختيار التقرير في **Report Definition** فيُعاد بناء الجدول من جديد. ولأنه يعيد بناء *كل* الأسطر، يضيع كل ما كتبته فيه بنفسك — قيم **Fill Manually** وأوصاف المدخلات — وعليك إدخاله ثانيةً، فدوّنه قبل إعادة الاختيار.
:::

## النوع الثالث: أداة مبنية على مسار كيان (Entity Flow Based)

تمكّن النموذج من **تنفيذ إجراء** في النظام عبر مسار كيان معرف مسبقًا — أي أن الذكاء الاصطناعي هنا لا يقرأ فحسب بل يُحدِث أثرًا.

في صفحة **Entity Flow Based**:

1. اختر المسار في حقل **Entity Flow**.
2. حدد **Entity Type Strategy** — على أي سجل يعمل المسار:

| الاستراتيجية | المعنى |
|---|---|
| **Runs On Single Entity Type** | يعمل على نوع كيان واحد محدد في حقل **Run Entity Flow On Type** |
| **Runs On Entity Type List** | يعمل على أحد أنواع محددة في **Run Entity Flow On Entity Type List**، ويختار النموذج النوع من بينها |
| **Runs On Any Document Type** | يعمل على أي نوع مستند |
| **Runs On Any Master File Type** | يعمل على أي ملف رئيسي |
| **Runs On Any Type** | يعمل على أي نوع كيان |
| **Does Not Need A Record** | لا يحتاج سجلًا — يُنفذ المسار مباشرة |

3. عرّف أي مدخلات إضافية يحتاجها المسار في جدول **Entity Flow Parameters** (نفس أعمدة مدخلات الاستعلام).

عندما تتطلب الاستراتيجية سجلًا، يضيف النظام تلقائيًا للنموذج مدخلين: نوع الكيان المستهدف (إن لم يكن محددًا في التعريف) وكود السجل أو معرفه. عند التنفيذ يُحضَر السجل، وتوضع قيم المدخلات في خريطة السجل، ثم يُشغَّل المسار — وأي فشل في المسار يُعاد للنموذج كرسالة خطأ.

![صفحة Entity Flow Based وجدول مدخلات المسار](./images/ai-tool-definition-entity-flow-ar.png)

## النوع الرابع: أدوات النظام (System Tool)

أدوات جاهزة مبنية داخل نما، يضيفها مدير النظام بسطر في جدول **System Tools Configuration**: كل سطر يحمل **Tool Class Name** (اسم صنف الأداة) ومعه حتى خمسة مدخلات نصية (Parameter 1–5) تكوّن سلوك الأداة إن كانت تحتاج تهيئة، وحقول وصف وعناوين تُملأ تلقائيًا.

![صفحة System Tool وجدول System Tools Configuration](./images/ai-tool-definition-system-tools-ar.png)

حقل **Tool Class Name** مزوّد بقائمة اقتراحات تعرض **كل أدوات النظام المتاحة في النظام** — تختار منها بالاسم.

::: warning الصنف ليس الأداة
ما تختاره في **Tool Class Name** هو *صنف*، ومعظم الأصناف تولّد أكثر من أداة: اختر `AITReadRecordTools` فينتهي الأمر بأداتين لدى النموذج، هما `<prefix>FindRecords` و `<prefix>GetRecord`. كما تعرض قائمة الاقتراحات الصنف باسمه الكامل — `com.namasoft.modules.ai.services.tools.AITReadRecordTools` — لذا حين تبحث عن أداة بعينها، ابحث عنها في عمود **الأدوات المتولدة** في الجداول أدناه وأضف الصنف الموجود في سطرها؛ أما كتابة اسم الأداة نفسها في الحقل فلا تجد شيئًا.
:::

::: warning أدوات تختفي بعد الترقية
قد يتغيّر اسم صنف أداة بين إصدار وآخر، أو ينقسم إلى صنفين. والسطر المحفوظ بالاسم القديم يحتفظ به بعد الترقية، فتتوقف أدوات ذلك السطر عن الظهور بصمت — في المساعد داخل النظام وفي كل عميل MCP على السواء. أما بقية أسطر التعريف نفسه فلا تتأثر، ويذكر سجل الخادم (log) السطر الذي تم تخطيه.

فإذا اختفت بعض الأدوات بعد ترقية، فافتح التعريف وابحث عن سطر لم تعد قائمة الاقتراحات في حقل **Tool Class Name** تعرض اسم صنفه، واختر الصنف الذي حلّ محله. وحفظ التعريف يرفض مثل هذا السطر على أي حال، بالرسالة:

*There is no AI tool class named {0}, choose one of the classes suggested on the field*

وليس لهذه الرسالة ترجمة عربية، لذا تظهر بالإنجليزية على الشاشات العربية أيضًا.
:::

### الأزرار أعلى الجدول

اختيار الأصناف واحدًا واحدًا من قائمة الاقتراحات بطيء، ومجموعة الأدوات نادرًا ما تنفع منقوصة — لذا تحمل الصفحة صفًا من الأزرار، يضيف كل منها مجموعة كاملة بضغطة واحدة:

| الزر | ما يضيفه | لمن |
|---|---|---|
| **إضافة أدوات التصدير (Add Export Tools)** | ٤ أصناف و١٢ أداة — فهم الكيان، والبحث في السجلات وقراءتها، واستيراد السجلات، ورفع ملفات المرفقات وتنزيلها | كل من يربط عميل MCP خارجيًا لقراءة البيانات والكتابة فيها |
| **إضافة أدوات التقارير (Add Report Tools)** | ٣ أصناف و٧ أدوات — قراءة استعلام التقرير وتشغيله وتصحيحه؛ وتشغيل لوحة معلومات ومراجعة ما يعرضه كل مخطط | مديرو النظام وفرق الدعم الباحثون عن سبب رقم خاطئ في تقرير أو لوحة معلومات |
| **إضافة أدوات التوجيهات والإعدادات (Add Term and Config Tools)** | صنفان و٤ أدوات — قراءة التوجيهات وإدخالات الإعدادات وتعديلها | مديرو النظام الذين يهيّئون المستندات |
| **إضافة أدوات المناقشات (Add Discussion Tools)** | صنفان وأداتان — إضافة مناقشة إلى سجل، وعرض مناقشات سجل | مساعد داخل النظام يعلّق على السجلات |

يضيف الزر الأسطر الناقصة فقط ويملأ وصف كل سطر تلقائيًا، فالضغط على زرين يتراكم، والضغط على الزر نفسه مرتين لا يغيّر شيئًا. واحذف بعد ذلك أي سطر لا تريده — فهكذا يبقى التعريف للقراءة فقط.

#### أدوات تصدير واستيراد السجلات (Add Export Tools)

أكثر مجموعة استخدامًا مع عملاء MCP الخارجيين: أربعة أصناف تولّد اثنتي عشرة أداة مجتمعةً، تتيح قراءة بيانات النظام، واستيراد سجلات جديدة بصيغة JSON، وإدخال ملفات المرفقات وإخراجها.

| اسم صنف الأداة | الأدوات المتولدة | وظيفتها |
|---|---|---|
| `AITEntityMetadataTools` | `<prefix>ResolveEntityType` و `<prefix>DescribeFields` و `<prefix>GetEnumValues` و `<prefix>GetEntitySchema` و `<prefix>SearchByTranslation` | كل ما يحتاجه العميل ليفهم الكيان قبل أن يستعلم عنه: تحويل مصطلح بالعربية أو الإنجليزية إلى نوع كيان، وسرد معرفات الحقول الصالحة للاستخدام كمعايير بحث، وعرض القيم المسموحة لحقول القوائم الثابتة، وإرجاع اسم الجدول والأعمدة الفعلية خلف الكيان، وتحويل مصطلح إلى أنواع كيانات وحقول وقيم قوائم دفعة واحدة |
| `AITReadRecordTools` | `<prefix>FindRecords` و `<prefix>GetRecord` | البحث عن سجلات بنوع كيان ومعايير، وقراءة سجل واحد كاملًا بصيغة JSON |
| `AITImportTools` | `<prefix>GetImportSchema` و `<prefix>ImportRecord` | عرض مخطط الاستيراد JSON لنوع كيان، واستيراد سجل أو أكثر إلى النظام |
| `AITAttachmentTools` | `<prefix>PrepareAttachmentUpload` و `<prefix>PrepareAttachmentDownload` و `<prefix>PrepareAttachmentDownloadById` | إعطاء المساعد رابطًا يُستخدم مرة واحدة لرفع ملف تُرفقه `ImportRecord` بعد ذلك بسجل، ورابطًا يُستخدم مرة واحدة لتنزيل ملف مرفق بسجل — يُحدَّد إما بالسجل والحقل، أو بمعرّف المرفق الذي تعيده `GetRecord` و`FindRecords` |

تفاصيل هذه الأدوات — مدخلاتها وأمثلة استخدامها — موثقة في صفحة [خادم MCP لنظام نما ERP](./ai-mcp-server.md).

::: info المرفقات تحتاج مساعدًا يستطيع تشغيل الأوامر
نداء أداة MCP يحمل نصًا فقط، لذا لا تمرّر أدوات المرفقات الملف نفسه: بل تعطي المساعد رابطًا، فيرسل المساعد الملف أو يجلبه بأمر `curl`. وهذا يناسب المساعدين القادرين على تشغيل الأوامر على جهازك — مثل Claude Code أو تبويب Code في Claude Desktop. انظر قسم «نقل ملفات المرفقات» في صفحة [خادم MCP لنظام نما ERP](./ai-mcp-server.md).
:::

#### أدوات التقارير (Add Report Tools)

معظم الأسئلة عن تقرير — لماذا هذا الإجمالي خاطئ، ولماذا اختفى هذا السطر، وأي مُدخل يتحكم في هذا الفلتر — هي في حقيقتها أسئلة عن استعلامه ومدخلاته، وهذه بضع مئات من البايتات من ملف تقرير حجمه ٧٠–١٢٠ كيلوبايت. وهذان الصنفان يتيحان للمساعد أن يقرأ هذا القدر بالضبط، وأن يشغّل التقرير ليرى الأثر، وأن يصحّح الاستعلام حين يكون الاستعلام هو الخطأ.

| اسم صنف الأداة | الأدوات المتولدة | وظيفتها |
|---|---|---|
| `AITReportReadTools` | `<prefix>GetReportQuery` و `<prefix>RunReport` | إرجاع مدخلات التقرير واستعلام SQL الخاص به وباستعلام كل مجموعة بيانات فرعية وكل تقرير فرعي فيه؛ وتشغيل التقرير بمدخلات محددة وإرجاع مخرجاته |
| `AITUpdateReportTools` | `<prefix>UpdateReportQuery` و `<prefix>UpdateReportContent` | استبدال استعلام مجموعة بيانات واحدة دون المساس ببقية ملف التقرير، أو استبدال ملف التقرير كاملًا |

يُشغَّل التقرير بصلاحيات المستخدم الذي تعمل الأداة نيابةً عنه، وتُفحص مدخلاته قبل تشغيله لا بعده. والتواريخ تبدأ باليوم (`31-01-2026`)، بخلاف أدوات السجلات. ويُستثنى من ذلك فلتر التاريخ المعروض كمنتقي فترة واحد: يأخذ قيمة واحدة على مُدخل المنتقي نفسه، `2026-07-01@2026-07-31`، أما مُدخلا التاريخ المخفيان خلفه فيُرفضان إن أُرسلا مباشرة. أما المُدخل الذي يشير إلى سجل — فترة مالية أو شركة أو فرع — فيقبل **كود** السجل كما يقبل معرّفه: تبحث الأداة عن السجل وتسلّم التقرير الصورة التي يقرؤها ذلك المُدخل بعينه.

::: warning التقرير الذي لا يفلتر شيئًا يجيب بكل شيء
هذا الفحص أهم مما يبدو. فحين لا تصل الفلاتر إلى التقرير لا يفشل شيء ولا يُنبّه شيء: يطبع التقرير العناوين نفسها والأعمدة نفسها وصفحة كاملة من أرقام معقولة تمامًا — لكل الفترات ولكل الفروع بدل التي طُلبت — وتظل المدخلات مطبوعة في ترويسته. ومن يقارن هذه الأرقام بسؤال عميل يخرج بخلاصة خاطئة وهو مطمئن.

لذلك ترفض `RunReport` التشغيل بدل أن تجيب بأرقام غير مفلترة: حين لا يكون المعرّف مُدخلًا لهذا التقرير، وحين تكون القيمة غير قابلة للتطبيق على المُدخل الذي أُعطيت له، وحين يسمّي مُدخلٌ يشير إلى سجل سجلًا غير موجود. كما تعيد الإجابة ذكر المدخلات التي طُبّقت فعلًا بالصورة التي أُرسلت بها إلى التقرير، حتى تُراجَع الأرقام في ضوء ما طُلب بدل أن تؤخذ على عِلّاتها. ويظهر المُدخل الذي يشير إلى سجل بمرجع السجل كاملًا — معرّفه ونوعه وكوده متصلة — وليس هذا ما يفلتر عليه التقرير: فالتقرير يأخذ منه الجزء الذي يقرؤه فقط، وهو الكود في الغالب.
:::

::: tip اقرأ الأرقام ولا تنظر إلى صورة
اطلب من `RunReport` صيغة **JSON** كلما كانت الأرقام هي المهمة: صف لكل سطر مطبوع، موسوم بالجزء الذي جاء منه (رأس الأعمدة، التفاصيل، تذييل المجموعة، الملخص …)، وخلاياه مصفوفة تحت رؤوس الأعمدة، والأرقام أرقامًا مجردة — والإجماليات الكبرى في صفوف الملخص في آخره. و**CSV** هي جدول التقرير مفصولًا بفواصل، و**TXT** (الافتراضية) الصفحة مرصوفة نصًّا، و**HTML** الصفحة المنسَّقة، وهي أكبرها حجمًا بفارق كبير. هذه الصيغ النصية تعود داخل الإجابة نفسها: أول 20,000 حرف افتراضيًا (`maxChars`، حتى 200,000)، أو بـ`tailChars` *آخر* هذا العدد من الأحرف بدلًا منها — وهناك إجماليات التقرير. ويختار `language` مسميات عربية (الافتراضي) أو إنجليزية. أما الصيغ الثنائية — PDF و XLSX و DOCX و RTF و ODT و ODS و PPTX و XLS — فتُحفظ على الخادم ويُرد عليها **برابط يُستخدم مرة واحدة وتنتهي صلاحيته بعد ثلاثين دقيقة** ليفتحه إنسان: يخدم الرابط الملف مرة ثم يحذفه. واضبط `ai-file-download-base-url` في ملف `nama.properties` إن أردت أن تحمل هذه الروابط عنوان الخادم المعلن بدل مسار نسبي.
:::

::: warning لا يُحفظ التقرير إلا إذا ظل قابلًا للترجمة
تترجم `UpdateReportQuery` و `UpdateReportContent` التقرير قبل إرساله، وترفضان حفظ ما لا يُترجم — فتعود الإجابة بشكوى المترجم نفسها والتقرير المحفوظ كما هو، وبذلك يكلّف الاستعلام الخاطئ نداءً فاشلًا لا تقريرًا معطوبًا. ويُعاد كتابة الملف بواسطة JasperReports نفسه: يبقى التصميم كما هو تمامًا، لكن تعليقات XML (ومنها ترويسة Jaspersoft Studio) والتنسيق الأصلي للمسافات لا تبقى.
:::

#### أدوات لوحات المعلومات (Add Report Tools)

عنصر لوحة المعلومات (widget) يُكتب على عمى. فاستعلامه وإعدادات مخططه تُحرَّر نصًا، ولا شيء يقول إن الاستعلام لم يُرجع صفوفًا، أو إن ربطًا عدّ كل فاتورة مرتين، أو إن الفلتر المتقاطع للفرع لم يصل إلى الاستعلام أصلًا — حتى يفتح أحدهم اللوحة وينظر. وهذه الأدوات الثلاث تتيح للمساعد أن ينظر بنفسه: تشغّل لوحة معلومات أو عنصرًا واحدًا منها وتجيب بما سيرسمه كل مخطط، أرقامًا يمكن مراجعتها.

| اسم صنف الأداة | الأدوات المتولدة | وظيفتها |
|---|---|---|
| `AITDashboardTools` | `<prefix>RunDashboard` و `<prefix>RunDashboardWidget` و `<prefix>PreviewDashboardWidget` | تشغيل لوحة معلومات (أو أحد تبويباتها) وإرجاع ما يعرضه كل عنصر فيها؛ وتشغيل عنصر واحد وإرجاع استعلام SQL الذي نفّذه أيضًا؛ وتشغيل عنصر كما سيكون بعد تعديل استعلامه أو إعدادات مخططه، دون حفظ أي شيء |

الإجابة هي ما رسمه الخادم لا مخرجات الاستعلام الخام: فئات المخطط وسلاسله بقيمها (بعد تطبيق ترتيبه وتجميعه و Top-N)، وأعمدة الجدول وصفوفه، وقيم بطاقة المؤشرات، ورسالة الخطأ لأي عنصر فشل. أما الألوان والخطوط وبقية التنسيق فتُحذف، لأنها معظم البايتات ولا تحمل شيئًا من المعنى. وتُقص القوائم الطويلة عند عدد الصفوف المطلوب في النداء، ويُذكر طولها الكامل بجانبها. وتُشغَّل اللوحة بصلاحيات المستخدم الذي تعمل الأداة نيابةً عنه، وتُطبَّق القيم الافتراضية لفلاترها المتقاطعة تمامًا كما على الشاشة؛ وتذكر الإجابة الفلاتر المتقاطعة والقيم التي طُبّقت، وتبويبات اللوحة إن كانت لوحة بتبويبات.

تُمرَّر الفلاتر المتقاطعة ومدخلات العنصر بالكود — كود الفلتر المتقاطع لا عنوانه. والفلتر الذي يشير إلى سجل يقبل **كود** السجل كما يقبل معرّفه، فالقيمة `{"nileLE":"01","nileFrom":"01-03-2026"}` تقصر اللوحة على الشركة `01` من مارس فصاعدًا؛ والفلتر الذي يقبل عدة قيم يأخذ قائمة، `{"nileLE":["01","03"]}`. أما الفلتر الخاص بعنصر واحد فمفتاحه كود الفلتر وكود العنصر معًا، `nileLE@nile-sales-branch`.

::: tip شاهد الاستعلام الذي نُفّذ فعلًا
استعلام SQL المحفوظ على العنصر ليس إلا نقطة البداية. فحين يصل إلى قاعدة البيانات تكون شروط الفلاتر المتقاطعة قد كُتبت فيه، واستعلام عنصر المعالج (wizard) قد أُعيد بناؤه، والمدخلات قد رُبطت بقيمها — لذا فقراءة الاستعلام المحفوظ لا تخبرك لماذا المخطط فارغ. وترجع `RunDashboardWidget` و `PreviewDashboardWidget` كل استعلام نفّذه العنصر (مقارنة الفترات تنفّذ استعلامين)، ومع كل واحد:

- الاستعلام كما وصل إلى قاعدة البيانات، والمدخلات ما زالت مكتوبة بصيغة `{name}`؛
- الاستعلام نفسه وقد كُتبت فيه كل قيمة، جاهزًا للصق في أداة SQL للقراءة فقط؛
- القيمة التي استلمها كل مُدخل — والمُدخل الذي يظهر بقيمة `NULL` مُدخل لم يصله شيء؛
- الأعمدة والصفوف التي أرجعتها قاعدة البيانات، قبل أن يجمّعها المخطط أو يرتّبها أو يقصّها؛
- المدة التي استغرقها، ورسالة الخطأ من قاعدة البيانات نفسها حين يفشل.

ومقارنة هذه الصفوف بسلاسل المخطط تفرّق بنظرة واحدة بين استعلام خاطئ وإعدادات مخطط خاطئة. ورؤية الاستعلامات تحتاج صلاحية تعديل عناصر لوحات المعلومات؛ ومن دونها تعود أرقام العنصر كما هي، وتذكر الإجابة سبب غياب الاستعلامات. أما `RunDashboard` فلا ترجع استعلامات — شغّل العنصر المعني وحده.
:::

تبدأ `PreviewDashboardWidget` من عنصر محفوظ، أو من الصفر، أو من الاثنين: تأخذ كود العنصر ومجموعة تعديلات — غالبًا استعلامًا جديدًا أو إعدادات مخطط جديدة أو نوع عنصر مختلفًا — وتشغّل النتيجة بالمدخلات والفلاتر المتقاطعة المعطاة، وترجع ما سيعرضه. لا يُحفظ شيء، فيستطيع المساعد أن يجرّب استعلامًا ويقرأ الأرقام ويصحّحه ويجرّب ثانية، ثم يحفظ العنصر بـ `ImportRecord` حين تصح الأرقام فقط. ولا يمكن بهذه الطريقة إلا تعديل حقول العنصر النصية والرقمية وحقول نعم/لا؛ أما جداوله (المدخلات وروابط الفلاتر المتقاطعة) فتؤخذ من العنصر المحفوظ كما هي.

::: warning تُرسَل `chartConfigJSON` إلى `ImportRecord` كنص
حين يُحفظ العنصر بـ `ImportRecord` يجب أن تُرسَل قيمة `chartConfigJSON` **كنص** JSON — الإعداد كله محوَّلاً إلى سلسلة نصية، `"chartConfigJSON":"{\"series\":[…]}"` — تماماً كما تأخذها `PreviewDashboardWidget`. أما الكائن المتداخل فيُقرأ كمرجع إلى سجل آخر، فيُحفظ العنصر بلا إعداد مخطط صالح. والصيغة المتداخلة الواردة في [المرجع التقني لـ BI](/ar/platform/bi/bi-module-technical-reference.md#10-SyG-lstyrd-ljmaay-JSON) لا تصلح إلا في ملف استيراد يُحمَّل بأمر **استيراد سجلات**.
:::

::: info المُدخل الذي لا يملكه العنصر يُذكر ولا يُرفض
مدخلات العنصر هي أسطر جدول **المدخلات (inputs)** فيه. والقيمة المرسلة لمعرّف ليس منها لا تصل إلى الاستعلام، فيُشغَّل العنصر من دونها — وأي `{name}` في استعلامه لا يطابق مُدخلًا يُربط بالقيمة `NULL`، وهذا يعني غالبًا ألا تعود أي صفوف. وتقول أدوات العنصر ذلك في إجابتها وتسمّي المدخلات التي لم تُطبَّق، حتى لا يُحسب المخطط الفارغ فترةً بلا مبيعات.
:::

::: tip قبل أن تستنتج أن خاصية غير موجودة
تصدر نما إصدارًا كل شهر، وهذا التوثيق و[ملاحظات الإصدارات](/ar/release-notes/) يصفان أحدث إصدار. والخادم الذي رُقِّي آخر مرة قبل صدور خاصية لا يملكها، ولن يُظهرها أي إعداد — فالمساعد الذي لا يعرف تاريخ الخادم الذي يخاطبه قد يقضي وقتًا طويلًا يبحث عن إعداد لم يوجد قط. وترجع `GetAppVersion` بصمة البناء والتاريخ الذي تعنيه والشهر الذي تحمل ملاحظات إصداره، وهو ما يحوّل «دعني أجد لك هذا الإعداد» إلى «هذه وصلت في إصدار مارس، وهذا الخادم على إصدار يناير».
:::

::: tip كيف تبني مساعدًا للقراءة فقط
فُصلت القراءة عن الكتابة في أصناف مستقلة عمدًا حتى تستطيع الاستغناء عن أصناف الكتابة: `AITTermAndConfigReadTools` وحده — بدون `AITTermAndConfigWriteTools` — يجعل المساعد يشرح كيف هُيِّئ التوجيه دون أن يملك وسيلة لتغييره، ومثله `AITReportReadTools` بدون `AITUpdateReportTools`، و`AITEntityMetadataTools` و `AITReadRecordTools` بدون `AITImportTools`. وكل زر مجموعة يضيف الشقين معًا، فاضغط الزر ثم احذف سطر الكتابة إن كان التعريف للقراءة فقط.
:::

::: info أدوات نظام خاصة بالوحدات
قد تضيف بعض الوحدات أدوات نظام خاصة بها تظهر في نفس القائمة. مثلًا توفّر وحدة الموارد البشرية أدوات لرصيد إجازات الموظف (للموظف الحالي أو لأي موظف). يتوسّع المتاح بحسب الوحدات المركّبة والمرخّصة.
:::

::: info أداة وثائق نما ERP تحتاج الإنترنت لا قاعدة المتجهات
ترسل أداة `AINamaERPDocsTool` السؤال إلى خدمة البحث في توثيق نما، فلا تحتاج شيئًا من قاعدة المتجهات — كل ما تحتاجه أن يصل الخادم إلى `https://nlm.namasoft.com` عبر HTTPS. وحين يتعذر ذلك تجيب الأداة بـ *Nama ERP documentation search is currently unavailable* متبوعة بالسبب.
:::

::: danger أداة SQL للقراءة فقط لا تتقيّد بصلاحيات السجلات
كل ما عدا ذلك في هذه الشاشة يمر عبر البوابات القياسية، فلا تُظهر الأداة للمستخدم أكثر مما تُظهره الشاشات. أما `AITReadOnlySQLQuery` فهي الاستثناء: تقرأ قاعدة البيانات مباشرة، فترى كل شركة وفرع وراتب وسعر بصرف النظر عمّا يُسمح لمستخدمها بفتحه. لا يُقبل سوى `SELECT` واحدة، وتُنفَّذ داخل معاملة يجري التراجع عنها دائمًا، فلا تستطيع تغيير شيء أبدًا — لكن اقصرها على مديري النظام عبر جدول **Security (Access Control)**. ويحدّد عمود المُدخل الأول لسطرها الحد الأقصى الافتراضي للصفوف في النداء الواحد (٢٠٠ افتراضيًا، و٥٠٠٠ كحد أعلى). وانظر [دعم أفضل باستخدام وكيل ذكاء اصطناعي](./ai-assisted-support.md) لمعرفة كيف تستخدمها فرق الدعم.
:::

::: info تُفحص العبارة بـJSqlParser 5.0 أولاً
قبل التنفيذ يتحقق **JSqlParser 5.0** من العبارة، وهو أشد صرامة من SQL Server نفسه: فأي عبارة لا يستطيع JSqlParser تحليلها تُرفض حتى لو كان الخادم ينفّذها. فعلى سبيل المثال، يرفض JSqlParser الصيغة `FOR XML PATH(''), TYPE).value(...)` و`ORDER BY` داخل استعلام فرعي `FOR XML PATH`، لذا استخدم `STRING_AGG(expr, ', ') WITHIN GROUP (ORDER BY …)` لتجميع النصوص. والأقواس المعقوفة `{…}` داخل النصوص الحرفية تُمرَّر إلى قاعدة البيانات كما هي.
:::

### أدوات إدارة الخادم

أغلب ما يفعله مدير النظام في صفحة **الأدوات المساعدة** (`/utils`) — معرفة من دخل إلى النظام الآن، وما الذي يعمل عليه الخادم، وهل صدر إصدار جديد — أسئلة يستطيع المساعد أن يجيب عنها بالقدر نفسه، والإجراءات القليلة الآمنة في أي وقت على تلك الصفحة يستطيع أن ينفذها بدلًا منك. يضيفها للمساعد صنفان:

| اسم صنف الأداة (Tool Class Name) | الأدوات الناتجة | الغرض |
|---|---|---|
| `AITServerAdminTools` | `<prefix>ListLoggedInUsers` و`<prefix>ListRunningTasks` و`<prefix>ListCaches` و`<prefix>ListWebSocketSessions` و`<prefix>ListCostProcessingRequests` و`<prefix>ListPendingAsyncSaves` و`<prefix>CheckForNewRelease` | الاطلاع دون أي تغيير: المستخدمون المتصلون الآن، والمهام الجارية (مهام الخادم والمهام التي بدأتها الشاشات)، وذاكرة التخزين المؤقت (الكاش)، واتصالات WebSocket المفتوحة، وطلبات إعادة احتساب التكلفة المخزنية المنتظرة، وسطور مستندات المخازن التي ما زالت تُحفظ في الخلفية، والإصدار الذي يعمل به الخادم مقارنةً بأحدث إصدار متاح له |
| | `<prefix>EvictCaches` و`<prefix>ReloadConfiguration` و`<prefix>RegenerateDefaultUIs` و`<prefix>RegenerateDefaultUIsForTypes` و`<prefix>RefreshCriticalErrors` و`<prefix>KillReport` | الإجراءات الآمنة: مسح الكاش في الشاشات والخدمات، وإعادة قراءة ملف الإعدادات والترجمات وإعدادات التطبيق دون إعادة تشغيل، وإعادة توليد الشاشات الافتراضية — كلها أو شاشات أنواع كيانات بعينها — (مع الإبقاء على تعديلات المستخدمين على الشاشات)، وإعادة فحص الأخطاء الحرجة بعد إصلاح أحدها، وإيقاف تقرير عالق |
| `AITServerDangerousTools` | `<prefix>UpgradeToLatestRelease` | ترقية الخادم إلى أحدث إصدار في إصداره الفرعي — وهي توقف Tomcat وتقطع اتصال كل المستخدمين. انظر أدناه |

الصنفان **لمديري النظام فقط**. يُفحص المستخدم الذي يدخل به الاستدعاء في كل مرة، ولا يستطيع جدول التحكم في الوصول أن يوسّع ذلك: التعريف الذي يضم هذين الصنفين يرد ببساطة برفض عندما يستدعيهما مستخدم ليس مديرًا. ويُسجَّل كل استدعاء كذلك في **سجل الإجراءات (Actions History)** باسم العملية مسبوقًا بـ`MCP:`.

إعادة توليد الشاشات الافتراضية تستغرق عدة دقائق، لذلك تبدؤها `RegenerateDefaultUIs` وترد فورًا، ويستطيع المساعد متابعتها بـ`ListRunningTasks`. لا تعمل إلا عملية توليد واحدة في الوقت نفسه — والعملية الثانية التي تبدأ قبل انتهاء الأولى تُرفض، ويُكتب الرفض في سجل التطبيق.

وحين تعرف الشاشات المتأثرة، فضّل `RegenerateDefaultUIsForTypes`: فهي تفعل ما يفعله زر **Regenerate GUI For Applicable Types Only** في تعديل الشاشة (Screen Modifier) أو شاشة العرض المخصصة (Custom List View)، في ثوانٍ لا دقائق، وتنتظر حتى تنتهي. أعطها `entityTypes` (مفصولة بفواصل، مثل `SalesInvoice,SalesReturn`)، أو `screenModifierCode` (الأنواع التي ينطبق عليها تعديل الشاشة)، أو `customListViewCode` (أنواع شاشة العرض المخصصة، ومنها الأنواع في سطور «مضافة إلى») — بأي مزيج، لكن واحدًا على الأقل.

::: danger الترقية تؤكدها أنت، لا المساعد
الترقية توقف الخادم: يُغلق Tomcat، ويُقطع اتصال كل المستخدمين ويضيع ما لم يحفظوه، ولا يستطيع أحد العمل لعدة دقائق. لذلك لا تنفذ `UpgradeToLatestRelease` الترقية بناءً على كلام المساعد أبدًا. قبل أي شيء يعرض عميل MCP عليك **أنت** نموذج تأكيد — العميل، والإصدار الحالي والإصدار الجديد، والمستخدمين المتصلين والمهام الجارية في تلك اللحظة — فيه اختيار قيمته الافتراضية **Cancel**، وخانة يجب أن **تكتب فيها اسم العميل كما هو تمامًا**. لا تبدأ الترقية إلا إذا اخترت **Upgrade now** وطابق الاسم؛ أما الرفض، أو إغلاق النموذج، أو كتابة الاسم خطأً، أو مرور دقيقتين دون رد، فكلها تترك الخادم كما هو.

النموذج يعرضه العميل نفسه ولا يكتبه المساعد، وردّك يعود إلى الخادم مباشرة، فلا يستطيع المساعد أن يملأه نيابةً عنك. ويتطلب ذلك عميلًا يستطيع عرض هذه النماذج (MCP *elicitation*)، وClaude Code يستطيع ذلك. أما العميل الذي لا يستطيع — ومنه [المساعد الذكي داخل النظام](./ai-assistant.md) — فيصله رفض ولا يحدث شيء. وترفض الأداة كذلك إذا لم يكن هناك إصدار أحدث، أو إذا انتهى عقد الدعم الفني للخادم.

بعد أن تبدأ الترقية يتوقف الخادم عن الرد لفترة؛ وعندما يعود تؤكد `GetAppVersion` (من `AITAppVersionTools`) الإصدار الذي يعمل به الآن.
:::

::: tip اترك الصنف الخطِر خارج التعريفات العادية
لا يضيف أي زر هذين الصنفين — اخترهما بالاسم من قائمة اقتراحات **اسم صنف الأداة**. وضع `AITServerDangerousTools` في تعريف مستقل مقصور على مديري النظام المسموح لهم فعلًا بالترقية، بدلًا من إضافته بجوار الأدوات اليومية. الخوادم التي تعمل بإصدارات أقدم من 20261004 لا تحتوي على هذه الأدوات.
:::

## أين تُستخدم هذه الأدوات؟

- **[المساعد الذكي داخل النظام](./ai-assistant.md)**: يستدعي الأدوات أثناء محادثته مع المستخدم للإجابة عن الأسئلة وتنفيذ الطلبات.
- **عملاء MCP الخارجيون**: أي عميل يدعم بروتوكول MCP — مثل Claude Desktop أو Claude Code — يستطيع الاتصال بالنظام واستخدام نفس الأدوات بنفس الصلاحيات. انظر [خادم MCP لنظام نما ERP](./ai-mcp-server.md).
