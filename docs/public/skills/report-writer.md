# Report Writer

Build Nama ERP reports that compile, run in both languages and stay maintainable.

---

## Step 1 — Pick the Route

| The user needs… | Route |
|---|---|
| Columns, totals and groups from one table and its references | **Report Wizard** (Administration → Reports → Report Wizard). No SQL, no jrxml. |
| The same, but the data needs a `UNION`, a hand-written join or a sign flip | Save the SELECT as a **Virtual Entity** (Administration → Reports → Virtual Entity), then pick it as the wizard's Main Table. |
| An exact layout, a crosstab, subreports, or SQL the wizard cannot express | A **hand-written jrxml** on a Report Definition (Steps 3–4). |

A report generated by a wizard is rewritten every time the wizard is saved (code, names, group, capabilities,
report type, fixed language and the jrxml itself). To change such a report, change the wizard, not the
generated design.

Detail: `namaerp-docs/docs/platform/reports/report-wizard-guide.md`,
`namaerp-docs/docs/platform/automation-and-rules/virtual-entity-guide.md`,
`namaerp-docs/docs/platform/reports/report-and-form-wizards.md`.

---

## Step 2 — Write the SQL

Nama runs on **SQL Server**: write T-SQL. Read the tables' columns from the data model first (a local
`namaerp-dm/docs/public/dm-json/<Entity>.json`, otherwise https://dm.namasoft.com). The full rule set, with worked
queries, is **Querying Nama Tables**: `namaerp-docs/docs/platform/reports/querying-nama-tables.md`
(https://docs.namasoft.com/platform/reports/querying-nama-tables.html). The rules a report breaks most often:

- **`commitedBefore = 1` on every document header.** A document has a row from its first save; drafts carry
  `commitedBefore = 0`. The column keeps that spelling (one *t*).
- **Lines have no `commitedBefore` column.** Join each line to its header and filter the header.
- **References are `<field>_id`** binary ids: `join Customer c on c.id = l.customer_id`.
- **`name1` is Arabic, `name2` is English.** Select both and choose in the layout with `NamaRep.name(name1, name2)`
  (Step 3).
- **Prefer `$P{x}` (bound) over `$P!{x}`** (pasted into the SQL as text). Use `$P!{}` only for a piece of SQL you
  build yourself, never for a user's answer.
- Check the query on its own first (the read-only SQL tool, or SSMS) with literal values, then add the parameters.

A minimal, working Nama report (it compiles on the JasperReports version Nama uses). It shows prompts with Arabic

### Rules the skeleton follows

- **`language="groovy"`** on `<jasperReport>`. Any other language is refused on save.
- **Prompt titles** come from the `arabic` and `english` properties. Every parameter without
  `isForPrompting="false"` (or an `ignore` property) becomes a prompt. The system parameters (`loginUserName1`,
  `loginLegalEntityLogo`, `reportName1`, …) are recognised by name and never prompted; their list is in
  `namaerp-docs/docs/platform/reports/reports-namarep-reference.md`.
- **Do not name a parameter** `legalEntity`, `branch`, `department`, `sector` or `analysisSet`: the save fails.
- **Defaults**: `defaultValue` takes `$today()`, `$monthStart()`, `$monthEnd()`, `$yearStart()`, `$yearEnd()`,
  `$previousMonthStart()` and the other `$…()` values.
- **A record prompt** needs `entityType`. `property` decides what the query receives: no `property` (or `id`) gives
  the record id (binary, compare with a `_id` column); `code`, `name1`, `name2` or any field id of that entity gives
  that value.
- **A list prompt** needs `class="java.util.List"` and `list=true` (plus `listType`, e.g. `java.util.Date`, when it
  is not a record). Filter it with `$X{IN, column, Param}`; an empty list becomes `0 = 0`, so "nothing chosen"
  means "all". Declare `<Param>_csv`, `_codecsv`, `_name1csv` or `_name2csv` as `java.lang.String` with
  `isForPrompting="false"` to print what was chosen.
- **An optional single record**: `($P{X} is null or $X{EQUAL, column, X})`.
- **Date range**: `$X{[BETWEEN], column, From, To}` is inclusive and drops a side left empty. For one range picker
  instead of two prompts, use a `java.lang.String` controller with `showAsDateRange=true`, `fromDateId` and
  `toDateId` naming two date parameters marked `isForPrompting="false"` (example in `reports-guide.md`, "Date Range
  Parameters").
- **An empty answer** reaches the query as `null`. To receive the smallest or largest possible value instead, add
  `<property name="type" value="&gt;"/>` (smallest) or `value="&lt;"` (largest).
- **Language**: `NamaRep.name(arabic, english)` returns the Arabic value when the report runs in Arabic and the
  English one otherwise, each falling back to the other when empty. Use it for every label and every name column.
- **Design LTR only.** Lay the report out left-to-right: text left-aligned, amounts right-aligned. When the report
  is saved, the Arabic version is produced by mirroring the layout: x positions are flipped, Left/Right alignment is
  swapped and crosstabs are reversed. Do not add language-dependent alignment or a second Arabic layout. To keep one
  element or band in place, give it the property `no-mirror`; to switch mirroring off for the whole report, tick
  **Do Not Mirror Content In Arabic** on the Report Definition.
- **Amounts**: `NamaRep.currencyPattern()` (or `NamaRep.currencyPattern($F{currencyCode})`) as the
  `patternExpression`. Other helpers: `namaerp-docs/docs/platform/reports/reports-namarep-reference.md`.

Printed forms (one record per print), subreports, logos and row-level security follow extra rules:
`namaerp-docs/docs/platform/reports/reports-guide.md`. Every parameter property is listed there under "Parameter
properties reference".

## Step 4 — Deliver It

**With the Nama MCP report tools** (`AITReportReadTools` and `AITUpdateReportTools` on the server's AI Tool
Definition):

1. Read the existing report with `<prefix>GetReportQuery` (report code). It returns every parameter (titles, type,
   allowed values, `defaultValueExpression`) and the SQL of each dataset and subreport, without the large file. Do
   not read a Report Definition with GetRecord for this.
2. To change only SQL: `<prefix>UpdateReportQuery` (report code, the complete new `sql`, optional `dataset`,
   `subreportId` or `resourceId`). It returns `previousSql`, which is how to undo. JasperReports rewrites the file,
   so XML comments and hand formatting are lost.
3. To replace the whole design: `<prefix>UpdateReportContent` (report code, complete `jrxml`), stored exactly as
   given.
4. Both compile first and save nothing that fails to compile, so a refusal leaves the report as it was.
5. A **new** report: create a Report Definition with `<prefix>ImportRecord` (read `<prefix>GetImportSchema` for
   `ReportDefinition` first): code, `name1` (Arabic), `name2` (English), `reportType` `UserReport`, and the design
   text in `reportContent`. Save and commit, not as a draft: the report is compiled only on commit. The first save
   builds the file from the text.

**Without MCP**, on **Administration → Reports → Report Definition**: upload the `.jrxml` into **Report File**, or
paste the text into **Report File Content** on the Advanced page and save (**Copy Content To Report** ticks itself
when the text changed). Report Type **Report** for a report run from the menu.

**System reports are frozen.** Saving a change to one is refused. Use **Duplicate**: the copy has **System** cleared
and is yours to change.

## Step 5 — Menu and Security

- **Menu**: the Reports menu lists the report groups. Put the report in a group with its **Group** field, or list it
  in a **Report Group** (Administration → Reports → Report Group) and tick **Automatically Add To Menu** to give
  that group its own menu entry.
- **Who may run it**: the **Security Capability Types** grid (Applicable For + Allow - Disallow), the **View
  Capability**, and **Security Type** / **Security Equivalent**. A grid of only Allow lines admits only the users it
  names. Order and details: `reports-guide.md`, "Who may run a report".

## Step 6 — Test

- **With MCP**: `<prefix>RunReport` with the code and a JSON object of parameters.
  - Dates are **`dd-MM-yyyy`**. A record parameter takes the record's code or id.
  - Several values of a list parameter are joined with `@A=@X`: `"Customers":"C0001@A=@XC0002"`.
  - A `showAsDateRange` controller takes `yyyy-MM-dd@yyyy-MM-dd` or a preset such as `ThisMonth`. Send the range on the
    controller's id: its hidden From/To date parameters are refused when sent directly.
  - `format: "JSON"` is the one to read figures from (totals are in the summary rows at the end).
  - Run it in Arabic (the default) and once with `language: "English"` to check both layouts.
  - RunReport refuses, rather than answering with unfiltered figures, when a parameter id is unknown or a record is
    not found. Compare one total with the same SELECT run on its own.
- **Without MCP**: run it from the menu in both languages and compare one total with the SQL.

## Known Errors

| Message | Cause |
|---|---|
| *Jasper design language must be groovy for report {0}* | `language` is not `groovy`. |
| *You cannot use the parameter ID {0} because it is a dimension id* | A parameter is named `legalEntity`, `branch`, `department`, `sector` or `analysisSet`. |
| *You can not make changes to the report {0} because it is a system report.* | Duplicate it and change the copy. |
| *The group parameter {0} must have isForPrompting set to false* | A `paramGroup` parameter is still a prompt. |
| *… has no stored XML text …* (report tools) | The text copy is filled on save: open the report, save it once, retry. |
| *This report has no parameter called …* (RunReport) | Use the ids GetReportQuery lists. |
